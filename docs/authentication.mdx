title: "Sign-up and API keys"
description: "Sign up by email code with two calls, then authenticate with an API key or OAuth."
---

There are no web pages to sign up on. Two JSON calls sign you up the first time and sign you in after that. Agents can run them on their own; a person only needs to read the code from their inbox.

## Sign up or sign in

<Steps>
  <Step title="Ask for a code">
    ```sh
    curl -s -X POST https://api.vidjutsu.ai/auth/email \
      -H 'Content-Type: application/json' \
      -d '{"email": "you@example.com"}'
    ```
    ```json
    {"attempt": "eyJ...", "expires_at": "2026-11-03T00:10:00.000Z",
     "next": "Ask the person for the code from the email. In the same message, ask whether this API key may change billing settings ..."}
    ```
    If you're an agent signing someone up, follow `next`: when you ask the person for the code, ask in the same message whether your key may also change billing settings and create or revoke keys. It gets full rights unless they say otherwise. See [Key scopes](#key-scopes).
  </Step>
  <Step title="Verify it">
    ```sh
    curl -s -X POST https://api.vidjutsu.ai/auth/verify \
      -H 'Content-Type: application/json' \
      -d '{"attempt": "eyJ...", "code": "123456", "name": "my laptop", "scopes": ["keys"]}'
    ```
    ```json
    {"api_key": "vj_live_...", "key_id": "...", "account_id": "...", "scopes": ["keys"],
     "status": "no_plan", "checkout_url": "https://checkout.stripe.com/...",
     "note": "Keep the API key: it's shown once. Send it as Authorization: Bearer <api_key>."}
    ```
    The first verify creates your account. Every verify creates a new API key, named by the optional `name`. Leave out `scopes` for a key with full rights, or send the ones the person chose (`[]` for neither).
  </Step>
  <Step title="Fund your wallet">
    A new account has `status: "no_plan"`. Open `checkout_url` in a browser to add a card and make your first $59 load. See [Pricing](/pricing).
  </Step>
</Steps>

The CLI runs the same two calls: `vidjutsu login`.

## Use your key

Send it on every call:

```sh
curl -s https://api.vidjutsu.ai/account -H "Authorization: Bearer vj_live_..."
```

The CLI and SDK read it from `VIDJUTSU_API_KEY`. A missing or invalid key is a 401 `unauthenticated`.

## Manage keys

| Call | CLI | |
| --- | --- | --- |
| `POST /keys {"name": "ci", "scopes": []}` | `vidjutsu keys create ci` | A new key. Its `secret` is shown only once. `scopes` is optional. |
| `GET /keys` | `vidjutsu keys` | Your keys with their `prefix` and `scopes`, never their secrets. |
| `DELETE /keys/{key_id}` | `vidjutsu keys revoke <key_id>` | The key stops working right away. |

Give each machine or agent its own key, so you can revoke one without touching the others. If a key leaks, revoke it and create a new one.

## Key scopes

Every key can work on projects: uploads, edits, renders, comments and share links. Two more rights are optional. A key gets both unless you say otherwise.

| Scope | Lets the key | Without it |
| --- | --- | --- |
| `billing` | Change auto-reload and the spend limit, and open the billing portal. | Checkout and top-up links still work, since a person pays on Stripe's page. |
| `keys` | Create and revoke API keys. | The key can still list keys. |

Choose them when the key is made: with `scopes` on `POST /auth/verify` for your first key, with `scopes` on `POST /keys` (the `create_key` MCP tool) after that, or with the checkboxes in the web app under Settings › API keys. Leaving `scopes` out means both. A key can't make a key with rights it doesn't have, and you can't change a key's scopes later: make a new key and revoke the old one.

```sh
# A key for a CI job that can't touch billing or other keys
curl -s -X POST https://api.vidjutsu.ai/keys \
  -H "Authorization: Bearer vj_live_..." -H 'Content-Type: application/json' \
  -d '{"name": "ci", "scopes": []}'
```

A call that needs a scope the key doesn't have gets a 403 `forbidden` with `reason: "missing_scope"`. Ask the person to make the change in the web app, or to give you a key with that scope. MCP clients that sign in with OAuth have full rights.

## OAuth for MCP clients

MCP clients that support OAuth can sign in at `https://api.vidjutsu.ai/mcp` without a key: the client discovers the sign-in server, registers itself and opens a sign-in page in your browser. Your account is created on your first call.

The browser sign-up page asks new users to prove they're human, so agents working alone should sign up with the two calls above and then use the API key. See [MCP](/mcp).
