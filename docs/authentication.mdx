---
title: "Sign-up and API keys"
description: "Sign up by email code with two calls, then authenticate with an API key or OAuth."
---

There are no web pages to sign up on. Two JSON calls sign you up the first time and sign you in after that. Agents can run them on their own; a person only needs to read the code from their inbox.

## Sign up or sign in

<Steps>
  <Step title="Ask for a code">
    ```sh
    curl -s -X POST https://api.vidjutsu.ai/v3/auth/email \
      -H 'Content-Type: application/json' \
      -d '{"email": "you@example.com"}'
    ```
    ```json
    {"attempt": "eyJ...", "expires_at": "2026-11-03T00:10:00.000Z",
     "next": "POST /v3/auth/verify with {attempt, code} from the email."}
    ```
  </Step>
  <Step title="Verify it">
    ```sh
    curl -s -X POST https://api.vidjutsu.ai/v3/auth/verify \
      -H 'Content-Type: application/json' \
      -d '{"attempt": "eyJ...", "code": "123456", "name": "my laptop"}'
    ```
    ```json
    {"api_key": "vj_live_...", "key_id": "...", "account_id": "...",
     "status": "no_plan", "checkout_url": "https://checkout.stripe.com/...",
     "note": "Keep the API key: it's shown once. Send it as Authorization: Bearer <api_key>."}
    ```
    The first verify creates your account. Every verify creates a new API key, named by the optional `name`.
  </Step>
  <Step title="Subscribe">
    A new account has `status: "no_plan"`. Open `checkout_url` in a browser to start Pro. See [Pricing](/pricing).
  </Step>
</Steps>

The CLI runs the same two calls: `vidjutsu login`.

## Use your key

Send it on every call:

```sh
curl -s https://api.vidjutsu.ai/v3/account -H "Authorization: Bearer vj_live_..."
```

The CLI and SDK read it from `VIDJUTSU_API_KEY`. A missing or invalid key is a 401 `unauthenticated`.

## Manage keys

| Call | CLI | |
| --- | --- | --- |
| `POST /v3/keys {"name": "ci"}` | `vidjutsu keys create ci` | A new key. Its `secret` is shown only once. |
| `GET /v3/keys` | `vidjutsu keys` | Your keys with their `prefix`, never their secrets. |
| `DELETE /v3/keys/{key_id}` | `vidjutsu keys revoke <key_id>` | The key stops working right away. |

Give each machine or agent its own key, so you can revoke one without touching the others. If a key leaks, revoke it and create a new one.

## OAuth for MCP clients

MCP clients that support OAuth can sign in at `https://api.vidjutsu.ai/mcp` without a key: the client discovers the sign-in server, registers itself and opens a sign-in page in your browser. Your account is created on your first call.

The browser sign-up page asks new users to prove they're human, so agents working alone should sign up with the two calls above and then use the API key. See [MCP](/mcp).
